## Part 2 - Bug found (no code change needed)

`/predicted` was showing **Argentina 56% / Spain 44%** as the most-likely champion,
i.e. still a coin-flip, a day after Spain actually won. Traced it: the 06:00 UTC
`lock-predictions` run (which includes `simulate_tournament.py`) executed at
**08:35 UTC**, but the Final's result wasn't written to `fixtures` by
`fetch_results.py` until **11:41 UTC** (next Update Results run, #301). So the sim
that ran that morning legitimately had no result to condition on yet for match 104
and fell back to simulating it, landing on Argentina as a mild favorite. This is the
existing conditioning logic (`load_actual_ko_winners` / `load_real_slots` in
`simulate_tournament.py`) working exactly as designed on stale-at-the-time data, not
a defect in it.

Verified by re-running `simulate_tournament.py 5000` locally against current data:
it correctly conditions on the real Final result and stores champion = Spain 100%,
Argentina 0%. That new sim row is now live; `/predicted` confirmed showing Spain
100% across the champion banner, title-odds bars, and the round-by-round table. The
`prediction-vs-reality` report card (anchored to the pre-tournament Jun 11 lock, by
design) is unaffected and still reads 83% (38 of 46 resolved slots called). No
commit needed since no source changed; this was a one-time timing gap that can't
recur now that the tournament has no more matches to resolve.
