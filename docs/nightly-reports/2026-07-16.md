Found and fixed a real, portfolio-visible bug: the Final and third-place
match were swapped throughout the system. `pipeline/data/bracket_wiring.py`
guessed the openfootball feed never numbers those two matches and assumed
103=Final, 104=third place; the live feed does number them, and it's

convention everywhere it was duplicated (pipeline wiring, its frontend
mirror, the simulation, and a query that would have crowned the
third-place winner as champion), verified end to end, and shipped it
(commit c247877). No other bugs found. No model experiment attempted
tonight - the two prior candidates (days-of-rest, bivariate Poisson) were
already discarded, and gradient boosting was closed for this cycle in the

## Part 2 - Bug Found and Fixed

**Symptom:** `verify_ready.py` showed 1 fixture in the next 48h with no
locked prediction. Investigating which one turned up something worse: the
fixture labeled "Final" (`fixtures.match_num = 103`, kickoff Jul 19,
venue New York) had France and England sitting in it - both semifinal
*losers*. The fixture labeled "third place" (`match_num = 104`, kickoff
Jul 18, Miami) had Spain and Argentina - both semifinal *winners*. Final
and third place were swapped.

**Root cause:** `pipeline/data/bracket_wiring.py`'s docstring said "The
Final and the third-place match carry no number in the feed; we use 103
and 104," and hardcoded `FINAL_NUM = 103, THIRD_PLACE_NUM = 104`. Pulled
the live openfootball feed directly and checked: it *does* number them,
and the assignment is the opposite of what the code assumed - `"num": 103`
is `"round": "Match for third place"`, `"num": 104` is `"round": "Final"`.
This was wrong from the day that code was written; it stayed invisible
for the whole tournament because both matches held unresolved slot refs
("W101"/"L101" etc.) until this week, when `resolve_knockout.py` filled
in real teams by matching the feed's `num` field against
`fixtures.match_num` - and pulled the third-place teams into the row we'd
labeled Final, and the finalists into the row we'd labeled third place.

Each fixture row's `stage`/`kickoff_utc`/`venue`/`match_id` were actually
already correct (`load_fixtures.py` sets those from the feed's own round
text and date, not from the wiring table) - only `match_num` and,
consequently, the team ids `resolve_knockout.py` filled from it, were
swapped between the two rows.

**Fix:**
1. Corrected the two `fixtures` rows directly: swapped `match_num` and
   `home_team_id`/`away_team_id` back so `match_num=103` (stage `3p`,
   Miami, Jul 18) holds France/England and `match_num=104` (stage `f`,
   New York, Jul 19) holds Spain/Argentina. No predictions existed yet for
   either match (both were still missing a locked prediction), so this
   never touched the append-only `predictions` table.
2. Fixed the root cause in `pipeline/data/bracket_wiring.py` (`WIRES`
   table and `FINAL_NUM`/`THIRD_PLACE_NUM`, now 103=third place,
   104=Final, with the docstring corrected to state this is confirmed
   against the live feed rather than guessed).
3. Fixed the same hardcoded assumption everywhere it was duplicated:
   `frontend/src/lib/bracket2026.ts` (the bracket-tree wiring mirror),
   `pipeline/jobs/simulate_tournament.py` (`ROUND_OF`'s final-round key
   and the champion lookup, both now derived from `FINAL_NUM` instead of
   a bare `103`), and `frontend/src/lib/queries.ts` (the "actual champion"
   query for the prediction-vs-reality report card was reading
   `match_num = 103`, which would have crowned the *third-place* winner
   as tournament champion once that match finished on Jul 18, a day
   before the real Final - now reads 104). Updated CLAUDE.md's
   documentation of the convention to match.
4. Verified: `resolve_knockout.py` and `fetch_results.py` clean (no
   warnings) after the fix. Re-ran `simulate_tournament.py 5000` in full;
   it now shows Spain and Argentina at 100% reach-final and splits
   champion odds 56.3%/43.7% between them, everyone else at 0% - correct.
   Ran `lock_predictions.py`, which locked the previously-missing France
   vs England third-place prediction (45.0% / 27.9% / 27.1%).
   `verify_ready.py` now shows 0 fixtures missing a prediction.
   `npm run build` passed. Loaded `/bracket` and `/predicted` in a local
   dev server against the real DB: Final correctly shows Spain vs
   Argentina, "reach the final" shows 2/2 slots resolved and called,
   initial predicted champion still correctly shown as Spain (from the
   pre-tournament simulation, unaffected). Checked the live production
   site after pushing: all six checked routes return 200, bracket page
   renders the corrected Final.

Committed and pushed to main: **c247877**.
